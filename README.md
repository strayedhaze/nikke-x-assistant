# NIKKE NOTE

NIKKE専用のX投稿・返信支援Webアプリ。vivo X100 Ultra（Android 16）のChromeを想定した、日本語のスマートフォン向けUIです。アプリ本体は **index.html 1ファイル**（HTML・CSS・JavaScript）。サーバー処理・外部API・外部ライブラリ・ログインは不要です。

## 使い方

1. 「新規投稿」または「返信」を選びます。
2. 紅蓮・リバーレリオ・スノーホワイトと、育成報告・攻略報告・交流の話題を選択。「このテンプレートを使う」で本文に反映します。各モード9種類、計18種類です。既存本文の置き換えには確認が出ます。
3. ［ ］を実際の出来事に書き換え、文章を編集します。テンプレートはゲーム性能や攻略の正しさを保証するものではありません。
4. 返信の場合は対象ポストのURLを入力します。HTTPSの `x.com` / `twitter.com`（www・mobileを含む）の `/ユーザー名/status/数字` または `/i/web/status/数字` を受け付けます。追跡パラメーターは開く際に除去します。URLの形式のみ検証し、ポストの存在・本文・返信可否は取得しません。
5. 本文・事実関係・返信先を確認してチェックを付けます。チェック前は共有と新規投稿画面を開くボタンが無効です。本文・モード・テンプレート選択・URLを変更したときや再読み込み時はチェックが外れます。返信の共有には有効な対象URLも必要です。
6. 「共有する」でAndroidの共有シートを開きます。**Xが共有先にない場合は「本文をコピー」してXに貼り付けてください。** 共有シートの終了は投稿完了を意味しません。
7. 新規投稿では「Xの新規投稿を開く」も利用できます。本文を含むXの投稿画面を開き、最後の送信は自分で行います。長い本文をURLで渡せない場合はコピーを使ってください。
8. **返信は「本文をコピー」→「元のポストをXで開く」→返信欄に手動で貼り付け**ます。共有による返信先の指定や、返信先への本文自動入力は保証しません。

文字数は絵文字のまとまりを1文字として数える目安です（Intl.Segmenter非対応時はUnicodeコードポイント単位）。X独自のURL短縮・日本語の加重文字数やプランの制限とは異なります。送信可否はXで確認してください。本文の入力上限は10,000 UTF-16コード単位です。

## 新しい文章作成機能

- **新規投稿**：「自由な話題」に書き、ニケを選ぶか「別のニケ名」を入力すると、話題とキャラ名を含むテンプレートをプレビューします。「このテンプレートを使う」で本文へ反映して編集できます。自由な話題が空なら既存の18テンプレートを引き続き使えます。
- **返信**：対象URLと相手の本文を手動で入力し、「返信候補を3種類作る」を押します。自然・丁寧・親しみやすいの3候補から選び、本文で自由に編集できます。本文の冒頭60コードポイントを引用する定型処理で、AIによる意味理解は行いません。生成後に相手の本文を変えると古い候補は消えます。
- 相手の本文・自由入力・履歴はHTMLとして実行せず、文字列として表示します。生成・共有・コピー・Xを開く操作はボタンで行います。本文の編集中に勝手に共有したり、Xを開いたりしません。

## ChatGPT連携支援（手動操作）

追加のAPIキー・サーバー・ビルドは不要です。投稿・返信の本文の上にある「ChatGPT連携（手動でコピー・貼り付け）」を開いて使います。

1. 「話題を選ぶ」でキャラクター（任意のニケ名も可）と話題を入力し、ChatGPT欄に補足情報・文章の雰囲気を指定します。返信では「相手のポスト本文」と「返信目的」も入力します。
2. 新規投稿では「ChatGPTで投稿文を作成」、返信では「ChatGPTで返信案を作成」で、日本語のプロンプトを端末内で作成します。この時点ではコピーも外部送信も行いません。
3. 表示されたプロンプトを読み、「プロンプトをコピー」を押します。コピー非対応・権限拒否時はプロンプト欄が選択されるので、長押し → すべて選択 → コピーで手動コピーし、「プロンプトを手動でコピーしました」にチェックを付けます。コピー成功または手動コピーの確認後に、起動ボタンが使えます。コピー完了から自動起動することはありません。
4. コピー後、まず「ChatGPTを開く（対応リンク）」をタップします。Androidが対応リンクとして解決できれば公式アプリが開きます。Chromeに留まった場合はNIKKE NOTEに戻り、「ChatGPTアプリを指定して開く」をタップしてください。「予備：ブラウザ版ChatGPTを開く」も利用できます。いずれも開くだけではプロンプトを渡しません。本人が貼り付け・内容確認・送信を行います。
5. ChatGPTから使いたい回答を手動でコピーし、「ChatGPTの回答を貼り付ける」欄へ貼り付けます。「本文に反映」で編集本文に反映します。既存本文の置き換えには確認が出ます。空欄は反映できず、10,000 UTF-16コード単位まで扱います。
6. 反映すると投稿前の確認チェックが外れます。事実・口調・返信先を見直し、チェックを付け直してから従来の共有・X画面での手動投稿を行ってください。選択済み画像は反映時に維持します。

プロンプトは自然でシンプルな日本語を基本に、過度な絵文字・ハッシュタグ・宣伝調・誇張を避け、未確認のゲーム情報や本人の実績・体験を創作しないよう指示します。ChatGPTの回答の正しさは保証できないため、必ず本人が確認してください。返信元本文は引用資料として扱うよう明示します。相手のURLや画像はプロンプトに含めません。

プロンプトの元になる入力を変更した場合・モードや履歴を切り替えた場合は古いプロンプトを消し、再作成を促します。補足情報・雰囲気・返信目的・貼り付けた回答は既存の作業用下書きと保存履歴に含めます。生成したプロンプト自体は保存せず、必要時に再作成します。現在の下書きを削除するとChatGPT入力欄も消去します（保存済み履歴は個別に削除）。

**X API・OpenAI API・有料外部APIは使用しません。ChatGPTのCookie・認証情報の取得、ChatGPTへの自動入力・自動送信・回答の自動取得もしません。** ChatGPT側のログインや利用条件は本人がChatGPT上で確認してください。無料で使える範囲や利用制限はChatGPTの提供条件に従います。個人情報や他人の非公開情報は貼り付けないでください。コピーしたプロンプトは端末のクリップボード管理に従います。

## Androidで公式ChatGPTアプリを開く

起動はコピーと別のタップで行います。JavaScriptのポップアップやコピー後の自動リダイレクトではなく、通常のリンクを使用します。

| 操作 | 動作 |
| --- | --- |
| ChatGPTを開く（対応リンク） | `https://chatgpt.com/` へ同じタブで通常のリンク遷移。Androidの検証済み対応リンクとユーザー設定に従います。まずこちらを試してください。 |
| ChatGPTアプリを指定して開く | Android Chromeのintent URLで公式パッケージ `com.openai.chatgpt` を指定。対象アプリがリンクを処理できない場合はWebのトップページへフォールバック。 |
| 予備：ブラウザ版ChatGPTを開く | `https://chatgpt.com/` を新しいタブで開きます。OS設定でアプリに切り替わる場合は、リンクを長押しして新しいタブで開いてください。 |

使用するintent URLは固定で、本文・プロンプト・返信先・画像を含めません。

```text
intent://chatgpt.com/#Intent;scheme=https;package=com.openai.chatgpt;S.browser_fallback_url=https%3A%2F%2Fchatgpt.com%2F;end
```

Chromeのintent起動は、ユーザーのジェスチャーや、アプリ側のエクスポートされた `BROWSABLE` な対応Activityが必要です。タイマー起動やアドレスバー入力からのリダイレクト等ではブロックされることがあります。本実装はボタン状のリンクを本人が直接タップする方式で、コピーの非同期処理と起動を同じ操作にまとめません。フォールバックはChromeに任せ、自動の再試行・画面切り替え検出・アプリのインストール検出は行いません。intentリンクはAndroid Chrome向けです。他の環境ではWeb版を使ってください。

**公式アプリがインストール済みでも、アプリ起動は保証できません。** Androidの対応リンク検証、ChatGPTアプリのバージョン・リンク対応、vivoの既定アプリ設定、Chromeの制限に依存します。アプリ側がルートURLを処理できない場合もあります。起動後の自動入力・自動送信は行いません。

プロンプトの再生成・元情報の変更・モード変更・履歴読み込み・再読み込みではコピー確認をリセットします。コピー完了待ちの間にプロンプトが変わった場合も、新しいプロンプトの起動ボタンを誤って有効にしません。コピー確認状態はlocalStorageには保存しません。

### vivo X100 Ultra / Android 16 / Chromeでの手動確認

1. Google Playの[公式ChatGPTアプリ（com.openai.chatgpt）](https://play.google.com/store/apps/details?id=com.openai.chatgpt)をインストール・更新します。Chromeも更新します。
2. Android設定の「アプリ」→「ChatGPT」→「デフォルトで開く／対応リンクを開く」で、`chatgpt.com` のリンクを開く設定を確認します。vivoのOSバージョン・言語によって項目名は異なります。
3. HTTPSのGitHub PagesからNIKKE NOTEを開き、プロンプト作成 → コピーを実行します。コピーだけでは画面が移らないことを確認します。
4. 対応リンクをタップし、公式アプリへ切り替わるか確認します。Chromeに留まった場合は戻ってintentの「アプリを指定して開く」を試します。自動で貼り付け・送信されないことを確認します。
5. アプリで手動で貼り付け・送信し、回答をNIKKE NOTEへ貼り付け、本文に反映すると確認チェックが外れることを確認します。
6. 対応リンクを無効にした場合や、アプリ未インストールの端末でも確認します。intentが解決されない場合のWebフォールバック、およびWeb版の予備ボタンが利用できることを確認します（設定は確認後に戻してください）。
7. サイトのクリップボード権限を拒否した場合、手動コピー欄と確認チェックで起動できることを確認します。起動しない場合もプロンプトをコピーしたまま、ホーム画面から公式アプリを手動で開けます。
8. 従来のX投稿・返信・画像共有・下書き復元・履歴編集も確認します。

参考：[Chrome公式のAndroid intent仕様](https://developer.chrome.com/docs/android/intents)、[Android公式のApp Links仕様](https://developer.android.com/training/app-links)。この開発環境ではAndroid実機やインストール済み公式アプリを使った起動検証は行えません。デスクトップChromiumのテストはリンク・操作順・回帰の確認であり、実機起動成功の保証ではありません。

## 画像共有

- 端末からJPEG・PNG・WebP・GIFを最大4枚、各10MB以下で選べます。ローカルプレビューと一括解除に対応します。画像選択・解除では確認チェックが外れます。
- 画像は画面のメモリ内だけで保持し、localStorageや履歴には保存しません。再読み込み、履歴読み込み、現在の下書き削除で解除されます。画像が必要な場合は改めて選択してください。
- 共有ボタンを押した際、`navigator.canShare({text, files})` で画像付きデータへの対応を確認してから、同じデータを `navigator.share` に渡します。共有までに非同期処理を挟まず、ユーザー操作の権限を維持します。画像なしでは既存のテキスト共有処理を維持します。
- files非対応、canShareなし／例外、共有失敗時は「本文をコピー」と**Xアプリでの手動画像添付**を案内します。画像を黙って捨てて本文だけ共有することはありません。Xの新規投稿画面を開くボタンは画像を渡せないため、画像は手動添付してください。
- 共有先が本文と画像の両方を受け取るかは端末・Xアプリ側に依存します。Xが一覧にない場合も、文章コピーと手動添付を使ってください。画像メタデータの除去・加工は行いません。

## 下書き履歴

- 「下書きを履歴に保存」で最大30件まで端末内に保存します。上限時は自動削除せず、不要な履歴の削除を案内します。保存は本人のボタン操作で行い、共有成功時に自動保存・送信済み判定はしません。
- 「編集」で履歴を作業欄に読み込み、「編集中の履歴を上書き保存」で同じ項目を更新できます。置換には確認が出ます。「別の下書きとして編集する」で、今の内容を次回別項目として保存できます。
- 再読み込み後は作業用下書きを復元しますが、履歴の編集対象は解除します。既存履歴を上書きするには履歴の「編集」から読み込んでください。
- 「削除」はその履歴だけを消します。編集中の本文や他の履歴は残ります。履歴は相手の本文・URLも含みます。共有端末では作業用下書きに加え、各履歴も削除してください。
- 保存容量不足・読み取り不可では案内を表示し、現在の本文編集を継続できます。画像は履歴に保存しません。

## 共有・コピーのフォールバック

- 画像なしでは既存通り、Web Share API非対応時は「共有の代わりにコピー」に切り替わります。`navigator.canShare` がテキスト共有不可を返す場合もコピーします。画像付きの場合は下記の対応確認を行い、非対応時は手動添付を案内します。
- 共有が拒否・失敗した場合はコピーボタンを案内します。キャンセル後に自動で再共有はしません。
- コピーには `navigator.clipboard.writeText` を使います。非対応・権限拒否時は本文を選択し、「長押し → すべて選択 → コピー」を案内します。
- 共有・コピーにはHTTPS（開発時はlocalhostも可）とユーザー操作が必要です。共有先は端末のインストール済みアプリ・OS設定に依存します。

## 保存とプライバシー

- 本文・モード・テンプレート選択・対象URLを、このブラウザ・オリジンの `localStorage` の `nikke-note.draft.v1` に保存します。作業用下書きは1件です。追加の入力欄も自動保存します。旧バージョンの下書きも読み込めます。履歴は別キー `nikke-note.history.v1` に保存します。
- 外部への自動保存、アクセス解析、外部フォント、API呼び出しはありません。X認証情報の取得、スクレイピング、自動クリック、自動送信もしません。
- 「共有する」で本文と選択中の画像をOSの共有機能に渡します。「Xの新規投稿を開く」では本文をURLパラメーターとしてXへ渡します。「元のポストを開く」では対象URLをXで開きます。いずれも明示的な操作時だけです。X側でログインを求められても本アプリは認証情報を受け取りません。
- コピーした本文はOSのクリップボード管理に従います。Xの投稿画面に渡した本文はブラウザ履歴等に残る可能性があります。
- 「保存した下書きを削除」はこのアプリの保存キーと画面の入力を消去します。保存履歴は残ります（各履歴の「削除」で消去）。X・クリップボード・ブラウザ履歴・他のサイトデータは消去しません。
- 保存データは暗号化されません。共有端末では利用後に削除してください。プライベートブラウジングやサイトデータ削除では消失する場合があります。保存不可の場合も編集できますが、閉じる前にコピーしてください。

## GitHub Pagesで公開

1. `index.html` と `README.md` をリポジトリの `main` ブランチのルートにコミット・pushします。
2. GitHubのリポジトリで **Settings → Pages → Build and deployment** を開きます。
3. **Source: Deploy from a branch**、**Branch: main**、**Folder: / (root)** を選び **Save** します。
4. デプロイ後、Pagesに表示されるHTTPS URLをAndroidのChromeで開きます。このリポジトリの標準URLは `https://strayedhaze.github.io/nikke-x-assistant/` です（実際の公開完了はGitHubで確認してください）。
5. 独自ドメインでもHTTPSを有効にしてください。APIキー・Secrets・ビルド工程は不要です。Pagesの利用可能範囲はリポジトリとプランに依存します。

## ローカル確認

ルートで次を実行し、同じPCのChromeから `http://localhost:8000` を開きます。これは開発確認用で、公開アプリにサーバー処理はありません。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Androidで別PCのHTTPアドレスを開く場合は共有APIが利用できないため、実機検証にはPagesのHTTPSを使ってください。ファイルの直接表示は保存・共有APIの挙動が異なるため推奨しません。

## 基本テスト

Node.js 22以降とChromiumを用意し、ルートで実行します。npm依存はありません。

```sh
node --test tests/basic.test.mjs
# Chromiumの配置が異なる場合
CHROMIUM_PATH=/path/to/chromium node --test tests/basic.test.mjs
```

実ブラウザを一時プロファイルとローカルHTTPサーバーで起動し、既存28項目にAndroid起動関連の4項目を加え、計32項目を検証します。18テンプレート、自由な話題とニケ名、3種類の返信候補、履歴の保存・再読み込み・編集・上書き・削除・容量エラー・30件制限、画像選択・プレビュー・形式チェック・画像付き共有・非対応・失敗・解除後のテキスト共有、URL検証、確認ゲート、文字数、共有・コピーの成功／非対応／失敗、Xを開くURL、360/412/480px幅の横はみ出しが対象です。対応リンク・公式パッケージ指定intent・WebフォールバックURL・コピー前の起動抑止・手動コピー確認・遅れて完了するコピー結果への対処、ChatGPTプロンプトの文脈・創作禁止指示、コピー成功／失敗、トップページだけを開く動作、回答反映時の再確認、下書き・履歴との互換性、外部への自動リクエストがないことも検証します。共有・クリップボード・外部ウィンドウはスタブに置き換え、XやChatGPTへの実際の送信はしません。コンテナ対応のためテスト用Chromiumは `--no-sandbox` を使用します。普段使いのChrome設定の変更は不要です。

### Android実機の確認項目（手動）

- vivo X100 Ultra / Android 16 / ChromeでPagesを開き、日本語入力・キーボード表示中のスクロール・縦横表示を確認。
- 本文編集で確認が外れ、チェック後のタップで実際の共有シートが開くことを確認。Xがない場合はコピーで貼り付ける。
- 共有キャンセル、クリップボード許可／拒否時の案内を確認。
- 返信URLから意図したポストを開き、手動で返信欄に貼り付ける。必要な送信は本人が行う。
- 再読み込みで下書きが復元され、確認が未選択になること、削除後は復元されないことを確認。

デスクトップChromiumの自動テストではAndroidの共有先一覧やvivo実機の動作までは保証できません。

実機では追加で、画像と本文の同時共有、画像共有キャンセル、手動添付、画像を外した後の従来通りのテキスト共有を確認してください。

ChatGPT連携の実機確認では、プロンプトコピー → ChatGPTを開く → 手動送信 → 回答を貼り付け → 本文に反映 → 確認チェックの再承認を行い、貼り付け時に画像選択が維持されることも確認してください。
